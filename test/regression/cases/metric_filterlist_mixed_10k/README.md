# `metric_filterlist_mixed_10k`

Measures what a **`metric_filterlist` that is half prefix rules** costs the
Agent, with **5,000 prefix entries** (`<name>*`) and **5,000 exact entries**.

This was originally the smallest tier of a three-tier sweep
(`metric_filterlist_mixed_10k`/`_50k`/`_100k`). The 50k and 100k tiers were
removed and this case's traffic volume was lowered (see "Traffic" below) after
the original 60 MiB/s config crashed the experiment in CI.

## Why

`pkg/util/strings.Matcher` has two arms: `prefixes`, scanned by `testPrefixes`
(binary search + `strings.HasPrefix`), and `exact`, scanned by binary search. A
hit pays for one arm, a miss pays for both. Per-entry `*` prefixes are new in
this branch, so nothing measures the prefix arm under load yet.

## Traffic (20 MiB/s total)

| generator | rate | names | path exercised |
|---|---|---|---|
| `background` | 16 MiB/s | random, as `quality_gate_metrics_logs` | evaluate, forward |
| `prefix_hit` | 1.5 MiB/s | `…bench.prefix.<idx><pad>.hit` | prefix arm, dropped |
| `exact_hit` | 1.5 MiB/s | `…bench.exact.<idx><pad>` | exact arm, dropped |
| `miss` | 1 MiB/s | `…bench.nomatch.<idx><pad>` | **both** arms, forwarded |

(Originally 60 MiB/s -- 48/4/4/4 -- which crashed this experiment in CI.)

Every name on the wire is exactly 88 characters in all four namespaces, so
hit-vs-miss differences cannot come from name length. Prefix *entries* are 84
characters: `prefix_hit` appends `.hit`, so a prefix-hit name equals no entry
and its drop can only have come from the prefix arm.

The two halves live in **disjoint namespaces** (`…bench.prefix` /
`…bench.exact`) because `NewMatcher` silently drops prefixes covered by shorter
prefixes and exact entries covered by a prefix — otherwise this tier would
compile to fewer than 10k live rules while still claiming 10k.

## Reading the results

The Regression Detector's baseline is the merge base of the base branch, which
has no prefix support and treats `foo.*` as a literal metric name: it filters
only the exact half and does strictly less work, so baseline-vs-comparison is
"feature off vs on", not a like-for-like regression.

## Regenerating

Originally generated by the smp-playground harness, not hand-authored:

```
cd experiments/regression/agent/metric_filterlist_scaling
python3 scripts/generate_filterlist_cases.py --mixed
# then copy cases/quality_gate_metric_filterlist_mixed_10k here, dropping the
# quality_gate_ prefix (this is a measurement case, not a quality gate)
```

That harness also validates the generated case, including against the real
production matcher (`scripts/validate_mixed_fixtures.sh`): compiled rule count,
every `prefix_hit`/`exact_hit` name dropped, every `miss` name kept. If
regenerating, re-apply the lowered traffic volume (see `lading/lading.yaml`)
and drop the 50k/100k copies -- they were removed here after this experiment
crashed at the original 60 MiB/s rate.

## Local run

```
smp local-run --experiment-dir test/regression \
  --case metric_filterlist_mixed_10k \
  --target-image <an image built from this branch>
```
