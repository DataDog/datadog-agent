## Review

### Top 3 observations

1. **Blocker — “durable remote controller” is not an established `episode-ctl` deployment mode; prove the remote runner before implementation.**  
   **Severity: High.** The existing controller is a process-local wrapper around `kubectl`, Helm, Docker/gcloud, local scenario files, and environment credentials. Its documented requirements are a local `KUBECONFIG`, `DD_API_KEY`, and `DD_APP_KEY` (`gensim/src/controller/README.md:151-190`), while deployment directly reads an absolute local scenario path and uses the runner’s credentials to create namespaces and Helm values (`gensim/src/controller/controller/controller.py:1114-1218`). The project’s current experiment plan explicitly classifies the `episode-ctl` guide as **“local source-bundle qualification only”** and says not to build scaled execution from laptop-owned controller processes (`docs/dev/gensim-global-1hz-scaled-experiment-plan.md:191-208`).

   **Minimal correction:** make the first implementation a single, version-pinned, one-shot job in an existing managed CI/job runner—not a new platform service. Its immutable job image must contain the tested `episode-ctl` version and required CLIs; it must obtain short-lived Kubernetes, Datadog, GCP, and archive credentials at runtime; use a read-only mounted/fetched content-addressed bundle; and write all state/evidence to durable object storage. A staging canary must demonstrate deploy, restart/reconcile, archive, and cleanup using that exact runner identity before accepting A/B work. Do not add a scheduler, queue, database, or fleet worker for the initial `active_pairs=1` campaign.

2. **Blocker — the proposed campaign state cannot safely retry an ambiguous external phase unless it records operation intent before invocation and reconciles concrete external identities.**  
   **Severity: High.** `episode-ctl` itself has only per-run mutable `run-result.json` recovery data, written for cleanup after an episode runner failure (`gensim/src/controller/README.md:151-174`); it does not provide campaign-level idempotency keys or a durable workflow state machine. `deploy()` treats an already existing namespace as acceptable and continues (`gensim/src/controller/controller/controller.py:1147-1168`). Therefore, after a runner crash between process launch and event-log append, a naïve resume can redeploy into an existing namespace, create a second release/build, or rerun an episode whose external action already began.

   **Minimal correction:** define a small, explicit durable state record per arm: `planned`, `deploy-intent`, `deployed`, `episode-intent`, `episode-terminal`, `verified`, `archive-intent`, `archived`, `teardown-intent`, `cleaned`, plus terminal blocked/failed states. Append and fsync/upload the intent event *before* launching each non-idempotent command; persist command ID, runner attempt ID, namespace/env, release name, build IDs, and result path. On restart, never rerun an intent blindly: reconcile namespace, Helm release/revision, pod labels/image IDs, Cloud Build status, episode result, archive object/checksum, monitors, and cluster-scoped RBAC. If the external state is ambiguous, transition to `blocked-reconciliation` and require an operator decision rather than starting a fresh attempt.

3. **Blocker — serialization avoids overlapping arm deploys but does not provide immutable workload identity; current `episode-ctl` will rebuild mutable service tags.**  
   **Severity: High.** Although `EpisodeController.deploy()` has an internal `skip_build` parameter (`gensim/src/controller/controller/controller.py:1114-1137`), the CLI deploy path does not pass it (`gensim/src/controller/controller/cli.py:82-106`). The experiment plan confirms that normal deploy rebuilds/pushes mutable scenario/service tags and says same-scenario A/B build/deploy must not overlap (`docs/dev/gensim-global-1hz-scaled-experiment-plan.md:449-455`). Serializing control then treatment is necessary, but it does not prove the two deployments ran the same workload bytes; it merely removes the concurrent write race.

   **Minimal correction:** retain the proposed `max builds=1`, `active pairs=1`, and `running episodes=2` limits, but make post-deploy workload-image digest equality a hard gate before either `run-episode` starts. Record every source/bundle hash, Cloud Build ID, resolved registry digest, pod `imageID`, Agent digest, and toggle. If source-equivalent A/B deployments resolve different non-Agent workload image IDs, mark the pair invalid, archive diagnostics, and clean up; do not run it. Do not claim build-once reuse until the CLI exposes and tests a content-addressed `--skip-build`/digest contract end-to-end.

### Overall assessment

The lifecycle and conservative limits are operationally feasible for a one-pair, remote one-shot pilot only after the remote-runner canary and intent-before-action reconciliation contract are implemented. The smallest safe solution is a thin job-wrapper/state machine around existing phase-separated `episode-ctl` commands, not a new controller platform or fleet capability; `GenerateCausalgenEpisodes` remains correctly out of scope while it is a stub.

### One thing other reviewers will miss

**The remote job’s own artifact and credential boundary is part of reproducibility, not just deployment plumbing.** The plan asks for hashes and runtime identities, but a remotely executed `episode-ctl` also requires a durable, non-secret record of the runner image digest, `episode-ctl`/Python dependency lock hash, rendered command lines with secret values redacted, kube-context/cluster identity, credential-provider identity, and the exact artifact fetch URI/version. Without those, the “same” bundle can produce non-reproducible behavior because Helm, kubectl, gcloud, archive dependencies, or cluster context changed beneath it. This is especially important because the CLI performs direct local-command execution rather than calling a stable remote API (`gensim/src/controller/controller/controller.py:1114-1218`).

### Residual risks after the minimal changes

- A one-shot runner still depends on availability of its external CI/job system, Kubernetes API, Cloud Build, Datadog APIs, and archival service; infra-only retries must remain bounded and reconciled.
- `episode-ctl` verification and archive commands need their optional dependencies and Datadog credentials (`gensim/src/controller/README.md:122-150`); validate the runner image contains them in the canary.
- Teardown must verify namespace, Helm release, monitors, and cluster-scoped RBAC deletion; existing guidance explicitly requires this after interruption (`docs/dev/gensim-global-1hz-scaled-experiment-plan.md:206-208`).
- The reviewed repository documentation currently treats this route as local-GKE-only. If the remote runner changes that supported operational boundary, update `gensim/src/controller/README.md`, `tools/gensim_global_1hz/README.md`, and `docs/dev/gensim-global-1hz-scaled-experiment-plan.md` in the same implementation.
