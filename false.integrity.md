## Review

**Overall assessment: No-go for pilot/confirmatory inference until the controller adds a frozen randomization/blinding contract and an evidence chain equivalent to the managed archive lineage.** The proposed controls are a solid operational starting point, but unique namespaces, `DD_ENV`, serialized builds, and checksums alone do not make paired A/B captures scientifically comparable or independently reproducible.

### Top 3 observations

1. **Blocker — fixed control-then-treatment deployment introduces an unregistered order/time confound and exposes the arm unless names are opaque.**  
   The stated sequence always deploys control before treatment. Concurrent `run-episode` reduces only part of that bias: deployment age, warmed caches/images, monitor registration, backend load, and ambient telemetry time still differ systematically. Further, a unique `DD_ENV` can leak the arm through alert context, monitor names/messages, archives, or evaluator input unless it is a neutral opaque identifier.  
   **Minimal change:** Before launching, persist and hash a blocked, seeded schedule that randomizes/alternates which arm is deployed and triggered first by scenario/family; record planned versus actual timestamps and deviations. Generate opaque arm-neutral namespace/environment aliases, keep the arm mapping in a separately access-controlled artifact, and run a leakage audit over rendered alerts, monitor text, archive metadata, and any investigator/judge-facing inputs.  
   **Evidence:** `docs/dev/gensim-global-1hz-scaled-experiment-plan.md:51` explicitly does not claim investigator blinding but requires blinded scenarios/judges; `:85` requires opaque identifiers and a private arm mapping; `:303` requires randomized capture and evaluation order with a preregistered seed.  
   **Severity:** blocker.

2. **Blocker — the proposed manifest/checksum list does not establish immutable identity continuity from incident execution to archived/evaluated evidence.**  
   Capturing source/bundle hashes, Cloud Build IDs, pod image IDs, Agent digest/toggle, and archive checksums is necessary but insufficient. It must bind: a unique run/attempt ID; exact pre-rendered A/B manifests and normalized allowlisted diff; actual command arguments and controller/`episode-ctl` version; trigger/recovery event IDs; raw verification output; archive object version/URI/checksum; and each downstream consumer’s input identity. Evidence must be write-once (or object-versioned with retention) and manifest entries must hash-chain/sign the prior entry and artifact digests. A checksum recorded in a mutable controller database or archive location cannot prove that the referenced object was not subsequently replaced.  
   This gap is especially important with `episode-ctl`: it is a local CLI, and `run_episode()` archives any existing local results before starting a run (`gensim/src/controller/controller/controller.py:1329-1347`). The controller must therefore allocate a unique attempt directory and externally immutable evidence destination before invoking it; it must never treat a reused local result file as the source of truth.  
   **Minimal change:** Define an `attempt_id` before every external call; use it in all output locations; append a hash-chained event that records request bytes/idempotency key before the call and returned identities after it; archive immutable raw artifacts first, then make a signed/materialized snapshot. Reject archive collisions, missing event-to-archive identity linkage, checksum mismatch, or post hoc artifact replacement.  
   **Evidence:** `docs/dev/gensim-global-1hz-scaled-experiment-plan.md:187` requires exact live-event → run-result → archive → Scenario Store → evaluator → crawler identity continuity and treats archive collisions/mismatches as stop conditions; `:253-278` requires a manifest, explicit state queue, and persisted idempotency/service IDs before retry; `:360-378` requires legal transitions and immutable-hash agreement.  
   **Severity:** blocker.

3. **High — “retry only infrastructure failures before any episode action” is not a sufficiently objective replacement rule.**  
   A failure before `run-episode` may still be treatment integrity evidence: e.g., the treatment Agent fails readiness, has a wrong image/toggle, produces unmatched telemetry, or its deployment differs from the normalized A/B contract. Retrying those failures until both arms are healthy selectively removes treatment harms. Conversely, an ambiguous controller timeout can lead to a duplicated action without an idempotency key and a reconciliation check. The existing CLI labels a non-zero episode script exit as `[INFRA]` (`gensim/src/controller/controller/controller.py:1391-1418`), so its label cannot be used as the scientific failure classification.  
   **Minimal change:** Preregister an arm-independent finite failure taxonomy and decide replacement eligibility from immutable pre-outcome evidence. Permit at most one replacement only for enumerated external failures with proof that no episode action/model investigation occurred; classify wrong Agent/config, arm-asymmetric readiness, telemetry/verification failure, identity mismatch, and any completed action as retained non-replaceable attempts. Reconcile any ambiguous request using the original idempotency key and external facts before retrying.  
   **Evidence:** `docs/dev/gensim-global-1hz-scaled-experiment-plan.md:249` requires an arm failure in pre-disruption qualification to be recorded rather than adapted; `:374-378` limits replacement to enumerated arm-independent pre-investigation failures and forbids treating an ambiguous retry as a fresh attempt; `:317-323` lists wrong Agent/config and identity/evidence failures as fleet stop conditions.  
   **Severity:** high.

### One thing other reviewers may miss

The plan’s **matching `DD_ENV` requirement can itself destroy blinding**. Names such as `scenario-control-*`/`scenario-treatment-*`, or an environment containing the toggle or cadence, are propagated into traces, logs, metrics, monitors, alerts, archive-derived context, and potentially judge inputs. Namespace isolation is useful, but the public identifiers must be neutral aliases; only the private immutable mapping may reveal the arm.

### Residual risks

- The repository’s own scaled-experiment plan says `episode-ctl` is for local source qualification, not scored captures: `docs/dev/gensim-global-1hz-scaled-experiment-plan.md:193-208`. The user may accept the remote path, but it needs an explicit deviation record and must reproduce the managed path’s identity/archive/reconciliation guarantees before results are used for causal claims.
- Serializing same-scenario build/deploy avoids mutable-tag races but does not establish matched workload bytes. Require a per-service resolved digest map from both runtime deployments and fail the pair if any workload image differs.
- Concurrent episode phases may compete for shared Datadog-org/backend resources. Preserve per-arm start/end timestamps, resource/load indicators, and verification windows so later analysis can identify or exclude materially asymmetric executions under a preregistered rule.
