# CWS review guidelines

Scope: `pkg/security/`.

## New kernel constants need a BTFHub sync

Kernels without BTF read offsets and struct sizes from the checked-in
`pkg/security/probe/constantfetch/constants_amd64.json` and
`constants_arm64.json`, falling back to the hand-written values in
`constantfetch/fallback.go` when an entry is missing.

Flag a PR that adds a constant request (a new name in
`constantfetch/constant_names.go`, used by `appendOffsetofRequest` or
`AppendSizeofRequest`) without adding that name to both JSON files. They are
regenerated by the `cws-btfhub-sync` workflow, run with `base_branch` set to the
PR branch (see the `cws-btfhub-sync` skill). Without the sync,
`TestOctogonConstants/btfhub-vs-fallback` fails on every pre-BTF kernel, or, if
the name is in `BTFHubVsFallbackPossiblyMissingConstants`, the test skips it and
a wrong fallback value goes unnoticed until the next sync.

Also flag a PR that adds a name to `BTFHubVsFallbackPossiblyMissingConstants`
(`pkg/security/tests/constants_test.go`) instead of syncing the JSON files, and
a new fallback value whose kernel-version boundaries aren't backed by the
BTFHub data for the covered distributions.
