# CWS review guidelines

Scope: `pkg/security/`.

## New kernel constants need a BTFHub sync

Kernels without BTF read offsets and struct sizes from the checked-in
`pkg/security/probe/constantfetch/constants_amd64.json` and
`constants_arm64.json`, falling back to the hand-written values in
`constantfetch/fallback.go` when an entry is missing.

Every request lives in `AppendProbeRequestsToFetcher`
(`pkg/security/probe/probe_ebpf.go`), which both the agent and the BTFHub
generator call. Read every line the PR adds to that function: each one that
registers a constant with the fetcher is a new request, whichever helper or
fetcher method it goes through and whether or not it is gated on the kernel
version. Flag a PR that adds a request without adding its name to both JSON
files. They are regenerated by the `cws-btfhub-sync` workflow, run with
`base_branch` set to the PR branch (see the `cws-btfhub-sync` skill). Without
the sync,
`TestOctogonConstants/btfhub-vs-fallback` (which only runs on kernels the BTFHub
data covers) fails wherever the fallback returns a value, since BTFHub returns
the error sentinel. If the name is in `BTFHubVsFallbackPossiblyMissingConstants`,
that sentinel-versus-value case is dropped instead, so a wrong fallback value
goes unnoticed until a sync gives BTFHub real values to compare against.

Also flag a PR that adds a name to `BTFHubVsFallbackPossiblyMissingConstants`
(`pkg/security/tests/constants_test.go`) instead of syncing the JSON files, and
a new fallback value whose kernel-version boundaries aren't backed by the
BTFHub data for the covered distributions.
